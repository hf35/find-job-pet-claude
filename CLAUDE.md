# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## О проекте

Личный однопользовательский сервис поиска работы:

1. собирает вакансии с hh.ru (позже — с других площадок) по сохранённым поискам;
2. отсеивает лишнее локальными правилами;
3. оценивает оставшиеся вакансии с помощью LLM относительно профиля пользователя;
4. готовит сопроводительные письма.

Автоотклик — только в будущем и только по явному подтверждению пользователя. Никогда не реализовывать отправку откликов без подтверждения и не обходить правила площадок (скрапинг вместо API, обход лимитов).

План и статус работ — в [docs/tasks.md](docs/tasks.md). Работаем по этапам из этого файла.

## Стек

- **Node.js 22**, **TypeScript** (strict, ESM)
- Бэкенд: **Fastify**, валидация — **zod**
- БД: **SQLite** (`better-sqlite3`) + **Drizzle ORM**, миграции применяются при старте
- Фронтенд: **React** + **Vite**, собирается в статику и раздаётся Fastify
- Планировщик: **node-cron** внутри приложения
- LLM: любой провайдер через **OpenAI-совместимый API** (по умолчанию Gemini free tier)
- Тесты: **Vitest**; линт: **ESLint** + **Prettier**
- Деплой: Docker-образ, собирается GitHub Actions и публикуется в GHCR

## Структура (целевая)

```
server/            # Fastify API, пайплайн, планировщик
  src/
    config.ts      # загрузка и валидация env
    db/            # схема Drizzle, миграции
    auth/
    sources/       # адаптеры площадок (hh/, ...) с общим интерфейсом
    pipeline/      # сбор → дедуп → правила → анализ
    rules/         # локальные фильтры (чистые функции)
    llm/           # клиент, промпты, схемы ответов
    routes/        # HTTP-маршруты
web/               # React SPA
docs/              # план, деплой, заметки по API
```

## Команды

Основные команды (корень репозитория):

```
npm install
npm run dev        # сервер + Vite
npm run build
npm start          # продакшн-запуск на :8844
npm run lint
npm run typecheck
npm test
```

## Соглашения

- Код, идентификаторы, комментарии и сообщения коммитов — на английском. Интерфейс и документация в `docs/` — на русском.
- Вся конфигурация — через env, валидируется при старте (`server/src/config.ts`). Новые переменные сразу добавлять в `.env.example` с комментарием.
- Никаких секретов в репозитории (ключи LLM, хеш пароля, `SESSION_SECRET`).
- Источники вакансий реализуют общий интерфейс и нормализуют данные в общую модель `Vacancy`; сырой ответ сохраняется в `raw`.
- Логика правил фильтрации и разбора ответов — чистые функции с unit-тестами. Для внешних API тесты используют сохранённые фикстуры, без реальных запросов.
- Ответы LLM всегда валидируются zod-схемой; невалидный ответ — повтор или ошибка, не «как есть».
- Изменения схемы БД — только через миграции Drizzle.
- Один этап из `docs/tasks.md` — один PR; отмечать выполненные пункты в том же PR.
- Перед завершением работы: `npm run lint && npm run typecheck && npm test`.

## Внешние API

- **hh.ru**: обязателен корректный `User-Agent` с контактом (из env). Соблюдать лимиты, ретраи с backoff. Актуальные требования сверять с `dev.hh.ru`; заметки — в `docs/hh-api.md`.

## Деплой

- Приложение слушает порт **8844**, данные — в volume `/data`.
- На VPS запускается через `docker compose`, порт проброшен только на `127.0.0.1`; HTTPS и домен обеспечивает Caddy пользователя (`reverse_proxy 127.0.0.1:8844`).
